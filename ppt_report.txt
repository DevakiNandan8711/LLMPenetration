Slide 2: Problem Statement
Modern penetration testing and CTF solving require expert knowledge, manual command execution, repeated observation, and step-by-step reasoning. Existing automated tools can scan or exploit only predefined cases, but they cannot independently plan the next logical action from terminal output.

Problem Statement:
To design and implement an autonomous LLM-driven penetration-testing system that can plan, execute, summarize, and iteratively solve multi-step CTF challenges in a secure sandboxed environment with minimal human intervention.

Slide 3: Motivation / Need for the Project
- Manual penetration testing is time-consuming and depends heavily on skilled experts.
- Traditional tools such as scanners and scripted automation do not adapt well to changing outputs.
- CTF-style labs are useful for cybersecurity training, but students need guided workflows and evidence.
- LLMs can reason over previous steps, generate commands, and summarize results.
- A safe sandbox is needed so command execution remains controlled and suitable for academic demonstration.

Slide 4: Objectives
- Build an autonomous agent that behaves like an ethical hacker in a controlled CTF environment.
- Use an LLM Planner to generate the next terminal command.
- Use an Executor to run commands inside a Docker sandbox.
- Use an LLM Summarizer to extract useful information from command output.
- Provide a React dashboard for logs, command timeline, metrics, graph, final flag, and report export.
- Support custom CTF challenges from the UI.
- Reduce run time by using a configurable max-step limit, defaulting to 8 steps instead of 24.

Slide 6: Modules / Components
Frontend Modules:
- Dashboard: overall run status and key metrics.
- Simulation Control: challenge selection, max-step setting, custom CTF creation, run/reset/stop controls.
- Live Terminal Output: streaming planner, executor, and summarizer logs.
- Planner Command Timeline: step-wise command history and summaries.
- Result Snapshot: target, difficulty, errors, final flag, report export.
- Technical Dossier: architecture, API, safety, evaluation, and stack.

Backend Modules:
- Planner API: generates commands using LLM reasoning.
- Executor API: runs commands in Docker or mock mode.
- Summarizer API: extracts relevant findings from raw output.
- Run Loop API: orchestrates Planner -> Executor -> Summarizer until flag, timeout, or max steps.
- Challenge API: lists and adds CTF challenges.

Slide 7: Workflow of the System
1. User selects a built-in or custom CTF challenge.
2. User sets max steps and starts the autonomous run.
3. Planner receives target details and previous summaries.
4. Planner generates the next command.
5. Executor runs the command in Docker sandbox.
6. Summarizer reads stdout/stderr and produces compact findings.
7. Dashboard updates logs, metrics, graph, and timeline.
8. Loop repeats until a flag is found, max steps are reached, or an error occurs.
9. User exports the final report as a text file.

8. Abstract
HackSynth is an autonomous penetration-testing system powered by Large Language Models. The system is designed for CTF-style cybersecurity environments where an AI agent can plan attack steps, execute terminal commands inside a sandbox, summarize command output, and continue the loop until a final flag is found or a step limit is reached. The project uses a React + Vite frontend, a FastAPI backend, LLM-based Planner and Summarizer modules, and Docker-based command execution. The dashboard provides challenge selection, custom CTF creation, real-time terminal logs, command timeline, metrics, graph visualization, and final report export. HackSynth demonstrates the potential of safe AI agents for cybersecurity training, research, and automated assessment.


Chapter 1 - Introduction

1.1 Global Introduction
Cybersecurity has become a major requirement for organizations, institutions, and individuals because modern systems are exposed to web vulnerabilities, network attacks, privilege escalation risks, and configuration errors. Penetration testing is used to identify such weaknesses before attackers exploit them. However, penetration testing is usually manual, time-consuming, and dependent on expert knowledge.

Large Language Models have shown strong reasoning ability in natural language and programming-related tasks. This creates an opportunity to use LLMs for guided cybersecurity workflows where the model can observe previous output, plan the next command, and summarize the result. HackSynth applies this idea to a controlled CTF-style penetration-testing environment.

1.2 Problem Definition
Existing automated tools can perform scanning or exploitation only when predefined rules are available. They do not fully understand multi-step context and cannot adapt like a human tester. HackSynth addresses this limitation by creating an autonomous loop where an LLM Planner generates commands, an Executor runs them safely, and a Summarizer converts output into useful context for the next step.

1.3 Objectives
- To design an autonomous LLM-driven penetration-testing agent.
- To automate multi-step CTF challenge solving in a controlled environment.
- To provide a safe Docker sandbox for command execution.
- To build a real-time dashboard for monitoring logs, metrics, graph, timeline, and result.
- To support custom CTF challenge creation.
- To generate final reports for evaluation and documentation.

Chapter 2 - Literature Survey

2.1 Brief Literature Survey
Cybersecurity automation has evolved from rule-based scanners to intelligent systems. Traditional tools such as Nmap and Metasploit are powerful but require human control. Machine learning tools are useful for anomaly detection and classification, but they usually do not plan or execute penetration-testing workflows. Recent LLM-based agents are capable of reasoning and sequential planning, making them suitable for experimental CTF automation.

2.2 Existing Works and Weaknesses
Manual Penetration Testing:
- Strength: accurate and expert-driven.
- Weakness: slow, expensive, and difficult to scale.

Scripted Tools:
- Strength: fast for predefined tasks.
- Weakness: cannot adapt to unexpected terminal output.

Machine Learning Cyber Tools:
- Strength: useful for detection and classification.
- Weakness: not designed for command planning or exploitation workflow.

LLM Assistants:
- Strength: can explain vulnerabilities and suggest commands.
- Weakness: often lack sandbox execution, autonomous loop, and structured reporting.

2.3 Potential of HackSynth
HackSynth combines LLM reasoning with safe execution and real-time visualization. Its main potential is to support cybersecurity education, CTF training, and research on autonomous agents in a controlled environment.


Chapter 3 - Methodology

3.1 Methodology
The project follows a modular agent-loop methodology:
1. Define challenge target and difficulty.
2. Planner generates next command using challenge context and previous summaries.
3. Executor runs the command inside Docker or mock mode.
4. Summarizer analyzes command output.
5. UI updates logs, graph, metrics, and timeline.
6. Loop continues until flag, max step, timeout, or error condition.
